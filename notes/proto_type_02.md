# コンポーネントの名前
- proto_type_02:
    - プレー中検出モデルの作成
    - 卓球プレイヤー or others の判定

## 概要
このコンポーネントは、卓球プレー映像からプレー中のシーンを自動的に検出し、切り抜く機能を提供します。YOLOv11-poseを用いて選手の骨格データを取得し、プレー中とプレー外の動作を判別します。

## 機能要件
- 動画ファイルを入力として受け取り、プレー中のシーンを抽出する。
- 学習させるデータについて
    - 初期モデルとしては多様性については考慮しない
    - 右対右のプレー映像，画角は固定，プレースタイルはドライブマンを想定する．

## 入力
- 動画ファイル（例: MP4, MOV形式）

## 出力
- 抽出されたプレー中のシーンを含む動画ファイル

## 処理フロー
1. 動画ファイルを受け取る
- Task1: プレイヤーorプレイヤー外の判定
    1. YOLOv11を用いて卓球台のバウンディングボックスの座標を獲得
        - 粗いフレーム数で獲得する(基本座標は同じであるため，カメラが移動した場合などを考慮する，かつ処理時間短縮のため)
        - 検出する卓球台は画面中央に近い卓球台とする
    2. YOLOv11-poseを用いて動画内の全人間の骨格データを取得
        - 粗いフレーム数で獲得する
    3. 各フレームにおいて，骨格データのバウンディングボックスと卓球台のバウンディングボックスの重なり具合を計算
        - 卓球台のバウンディングボックス座標に対して，近いかつサービスらしき動作をしているタイミングを獲得(LSTMなどの判定処理)
        - 骨格データの運動量を計算（例えば，審判などは停止しているから除外したい）
- Task2: プレイ中のシーン抽出
    - 入力として受け取るのはTask1の結果，結果自体がサービスシーンからであることを想定している．
    1. Task1の結果をもとに，プレイヤーが卓球台の近くで骨格データを抽出
    2. プレイヤーの動きが活発なフレームをプレー中と判定
    3. 連続するプレー中のフレームをまとめて抽出
    4. 判定モデルLSTMを用いて，プレー中シーンの精度向上を図る

### 簡略化フロー
- Step1: 卓球台検出 (0.10fps)
  - 卓球台座標取得
  - カメラに近い側 / 遠い側の領域を定義

- Step2: プレイヤー候補検出 (1fps) 
  - 条件1: 卓球台の「両側」に分けて判定
    - 手前側エリア: 通常の閾値
    - 奥側エリア: 閾値を緩和（conf=0.25など）
  
  - 条件2: 運動量判定も両側で別基準
    - 奥側は小さく映るので運動量も小さくなる
    - 相対的な運動量で判定
  
  - 条件3: Tracking継続性の活用
    - 一度検出されたIDは、検出が途切れてもtrack_buffer期間（例:30フレーム=30秒@1fps）はプレイヤー候補として保持

Step2.5: プレイヤー確定 ← 新規追加
  - Step2で得られた複数の候補から最終的に2人を選定
  - 選定基準:
    1. 卓球台の両側に配置されている
    2. tracking継続時間が長い
    3. 総運動量が多い
  
  → これで奥側選手の検出が一時的に途切れても
     tracking IDと時系列情報から復元可能

Step3: Dense骨格データ取得 (30fps)
  - Step2.5で確定したプレイヤーの出現区間
  - ここでも track_buffer を活用して途切れ対策

Step4: LSTM判定 + 補間処理 ← 修正
  - プレー中判定
  - 骨格データが途切れた区間は時系列補間
    例: 前後5フレームの平均で欠損フレームを補完

## コンポーネント定義（想定）
    TableDetector (卓球台検出コンポーネント)
    ├─ 責務: 卓球台の検出と情報管理
    ├─ 入力: フレーム画像
    └─ 出力: TableInfo (bbox, 前後領域定義)

    PlayerTableAnalyzer (プレイヤー-卓球台関係分析コンポーネント)
    ├─ 責務: プレイヤーと卓球台の位置関係判定
    ├─ 入力: TableInfo, プレイヤーbbox
    └─ 出力: 位置関係情報 (near/far, left/right, 距離)

    PlayerDetector (プレイヤー検出コンポーネント)
    ├─ 責務: プレイヤー候補の検出・tracking・確定
    ├─ 入力: フレーム画像, TableInfo, PlayerTableAnalyzer
    └─ 出力: 確定したプレイヤーのtracking ID一覧

## テストケース
- 正常系: 有効な動画ファイルを入力として与え、プレー中のシーンが正しく抽出されることを確認する。
- 異常系: 存在しない動画ファイルを入力として与え、適切なエラーメッセージが表示されることを確認する。

## その他
- [] 検出安定性を向上させる技術的対策
  - マルチスケール検出
    - config
      - "imgsz": 1280,  # デフォルト640より大きく
      - "conf": 0.3,    # 信頼度閾値を下げて検出漏れを防ぐ
      
  - Tracking アルゴリズムの強化
    - YOLOv11のデフォルトtrackingではなく、より堅牢なものを使用
    - tracker_config
      - "tracker_type": "bytetrack",  # or "botsort"
      - "track_high_thresh": 0.3,
      - "track_low_thresh": 0.1,
      - "new_track_thresh": 0.4,
      - "track_buffer": 30,  # ←重要: 検出が途切れても30フレーム追跡継続
      - "match_thresh": 0.8,
